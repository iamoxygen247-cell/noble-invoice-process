Function Keys — Fix Dead Keys / Rotate

Noble Invoice Processor · func-invoiceprocess-westus · get a fresh key, replace it at every consumer, verify

app: func-invoiceprocess-westus endpoint: /api/process-invoice auth_level: FUNCTION

All keys issued before 2026-07-14 are dead. On Flex Consumption the key secrets live in the app's host storage account. That account (stinvoicefuncappwestus) was deleted and replaced by stinvoicefuncdevwestus, so the host minted a completely new key set — the old values are unrecoverable and every stored copy (Power Automate connection, Postman, notes) returns 401 Unauthorized until replaced. The same runbook applies to any future rotation (deliberate renewal or leak response).

Placeholders used throughout: <HOST> = func-invoiceprocess-westus-exg8hzhke9c9ajgs.westus-01.azurewebsites.net (the hashed default domain — the bare func-invoiceprocess-westus.azurewebsites.net does not resolve), <KEY> = the function key value. Never write a real key into this repo, a doc, or a screenshot.

1Get a fresh key

Portal (recommended — immune to the local TLS-inspection problem)

  1. Go to portal.azure.com → search Function App → open func-invoiceprocess-westus.
  2. Least privilege (use this for Power Automate): on Overview open the Functions tab → select process_invoice → Function keys tab → next to default click Show value → copy. This key opens only the /api/process-invoice endpoint.
  3. App-wide alternative: left menu → Functions → App keys → under Host keys (all functions) copy default. Broader than needed; acceptable for ad-hoc testing. Never hand out _master — it also opens the admin API.

CLI / scripted (fallbacks)

# az (may die on this machine's TLS-inspector resets, WinError 10054 — just re-run, or use the ARM recipe)
az functionapp keys list -g rg-content-understanding-dev -n func-invoiceprocess-westus `
  --query "functionKeys.default" -o tsv

The reliable scripted path on this machine is the ARM REST call (POST …/host/default/listkeys) with the truststore retry recipe — see the 2026-07-14 entries in docs/ai/troubleshooting.md. Capture the key into $env:FKEY; never echo it.

2Replace the key at every consumer

A — A Power Automate custom connector / connection already exists

  1. Go to make.powerautomate.com → pick the correct environment (top right).
  2. Left menu → Connections (under Data; click More if hidden).
  3. Find the connection bound to the invoice custom connector → ⋯ → Edit — an API-key connection re-prompts for the secret → paste the new <KEY> → save.
  4. If no Edit is offered: create + New connection for the same connector, paste the key, then open the flow → every action that uses the connector → Change connection → pick the new one → save the flow → delete the stale connection.
  5. While you are there, open the custom connector definition and confirm its Host is the hashed domain <HOST>. An older build may carry the bare hostname, which never resolves — that failure looks like a network error, not a 401.

B — Connector not built yet

Nothing to repair. Use the fresh <KEY> and the hashed <HOST> when you create the connector + connection (walkthrough: docs/power-automate-design.html).

C — Ad-hoc copies

Postman collections, terminal history, OneNote/notes, saved test.py command lines: replace the key or delete the copy. Keys never go into git — local.settings.json holds no function keys and stays gitignored.

3Verify

Power Automate side

  • Custom connector → Test tab → invoke with a small payload, or drop a test PDF into the SharePoint library and watch the flow run.
  • Expect HTTP 200 with a routingDecision in the body.
  • 401 → the connection still holds a stale key (redo step 2A). DNS / "name not resolved" → the connector Host is the bare hostname (step 2A.5).

Scripted, from this machine

# $env:FKEY holds the fresh key (from step 1); truststore bootstrap beats the TLS inspector
.\.venv\Scripts\python.exe -c "import truststore; truststore.inject_into_ssl(); import os, runpy, sys; sys.argv = ['test.py', '--base-url', 'https://func-invoiceprocess-westus-exg8hzhke9c9ajgs.westus-01.azurewebsites.net', '--key', os.environ['FKEY'], '--file', '.\\samples\\trade1.pdf']; runpy.run_path('scripts/test.py', run_name='__main__')"

Expect HTTP 200, a routingDecision, and a fresh ledger row in stinvoicedevwestus / InvoiceExtractProcessLog.

Deliberate rotation / leak response. Portal → App keys (or the function's Function keys tab) → Renew key value on the compromised key, then repeat steps 1–3 of this runbook. Renewing invalidates the old value immediately — update consumers right away.
