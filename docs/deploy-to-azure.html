Deploy to Azure — End-to-End

Noble Invoice Processor · decision-engine Function + Content Understanding analyzer

remote build: on deploy subpath: functionapp runtime: Python v2

Two things deploy separately. The Function code (the 8-digit PO/job gate rides along with it) and the CU analyzer (the 8-digit prompt — a data-plane change that must be re-provisioned). Do both. Your .vscode/settings.json sets scmDoBuildDuringDeployment: true, so Azure rebuilds from requirements.txt server-side (the new tzdata installs automatically). local.settings.json is never deployed — the app reads its config from Azure Application Settings.

Replace these placeholders throughout: <APP> (Function App name), <RG> (resource group), <HOST> (default host name), <KEY> (function key).

0Pre-flight (local)

cd "C:\Users\georg\dev\Noble Homes\Invoice Extractor\noble-invoice-process"

Note the <APP> and <RG> from step 3.

1Re-provision the CU analyzer (the 8-digit prompt)

Editing analyzers\create-generalinvoice-analyzer.json changes nothing live. Push it to CU:

# AZURE_CU_ENDPOINT is required (the script has no baked-in default) — point it at dev:
$env:AZURE_CU_ENDPOINT = "https://invoice-processing-dev-resource.services.ai.azure.com/"
.\.venv\Scripts\python.exe scripts\create_analyzer.py

Expect Done. analyzer_id=generalinvoice…. Auth uses your az login; your identity needs Cognitive Services User on invoice-processing-dev-resource. This overwrites the live generalinvoice analyzer (allow_replace=True).

2Deploy the Function code

Option A — Core Tools (CLI)

cd "C:\Users\georg\dev\Noble Homes\Invoice Extractor\noble-invoice-process\functionapp"
func azure functionapp publish <APP> --build remote

Option B — VS Code

Azure extension → Workspace → Deploy to Function App… → pick <APP>. It uses deploySubpath: functionapp automatically; confirm the overwrite prompt.

Either way, wait for the upload + remote build to finish and the process_invoice function to be listed.

Set a missing one:

az functionapp config appsettings set -g <RG> -n <APP> --settings "AZURE_STORAGE_ACCOUNT=stinvoicedevwestus"
Identity / RBAC — the part az login can't simulate (production runs as the managed identity, not you). The app's identity id-invoice-processing-dev must have Cognitive Services User on the CU resource and Storage Table Data Contributor on stinvoicedevwestus. Leave AZURE_CU_KEY and AZURE_TABLES_CONNECTION_STRING unset to stay keyless. Do not copy local's AzureWebJobsStorage=UseDevelopmentStorage=true to Azure — keep the platform's real storage connection.

4Get the base URL + function key

# Base URL
az functionapp show -g <RG> -n <APP> --query "defaultHostName" -o tsv   # -> <APP>.azurewebsites.net

# Function key (route auth_level is FUNCTION)
az functionapp keys list -g <RG> -n <APP> --query "functionKeys.default" -o tsv

Call these <HOST> and <KEY>.

5End-to-end smoke test the deployed Function

Use the dedicated deployed-function tester (scripts\verify_fn.py, stdlib only):

cd "C:\Users\georg\dev\Noble Homes\Invoice Extractor\noble-invoice-process\scripts"

# 1. Validation path (no Azure data touched) -> expect HTTP 400
python verify_fn.py --base-url "https://<HOST>" --key "<KEY>" --bad-payload

# 2. Real invoice -> expect HTTP 200 + a routingDecision, writes a ledger row
python verify_fn.py --base-url "https://<HOST>" --key "<KEY>" --file "..\samples\trade1.pdf"

# 3. 8-digit PO rule end-to-end: a non-8-digit PO should now route to REVIEW_B4_CRITICAL_FIELD
python verify_fn.py --base-url "https://<HOST>" --key "<KEY>" --file "..\samples\landscaping.pdf"

# 4. Re-post the same source id -> alreadyProcessed:true (gate A1)
python verify_fn.py --base-url "https://<HOST>" --key "<KEY>" --file "..\samples\trade1.pdf" --source-id <SID_FROM_STEP_2>

Add --insecure to any call if a corporate proxy intercepts TLS. Watch for --> routingDecision: … and no ledgerWriteError. A 502 = CU/role issue; 500 = storage/role issue (Phase 3).

6Confirm the ledger write in Azure

az storage entity query --account-name stinvoicedevwestus --table-name InvoiceExtractProcessLog `
  --auth-mode login --num-results 5 `
  --query "items[].{rk:RowKey, status:Status, decision:RoutingDecision}" -o table

Expect rows with Status=Extracted and the routing decision from your test posts.
