Diagnostics Sidecar — Design & Decision Record

Noble Invoice Processor · persisting the evidence needed to troubleshoot a bad extraction

date: 2026-07-10 store: blob sidecar + ledger pointers retention: 90 days (lifecycle rule) tooling: scripts/diag.py

1Problem

Before this change, the pipeline's only durable store was the InvoiceExtractProcessLog table, and it held only the routing decision plus policy stamps (RoutingDecision, BillType, SubBillType, PolicyBucket, PolicyVersion, DefaultedFields, IsHandwritten, filename/URL, timestamps). Everything needed to diagnose a bad extraction was discarded on every run:

  • the raw Content Understanding result (per-field values, confidences, source detail) — returned by cu_client, consumed by gates.evaluate, then dropped; never logged;
  • the extracted field values — present only in the HTTP response to the Power Automate flow;
  • the analyzer id in effect — analyzers are re-provisioned in place (scripts/create_analyzer.py uses allow_replace=True), so runs under different prompt revisions were indistinguishable;
  • any failure detail — a failed CU call left a row stuck at Status="Received" with no reason recorded.
Why a re-run is not a substitute. CU classification labels and confidences flap run-to-run on borderline documents (documented in docs/ai/troubleshooting.md). Re-processing the SharePoint file does not reproduce the original run; only the stored raw result shows what CU actually said at the time.

2Decision record

OptionDecisionWhy
Store the whole CU JSON in the ledger Rejected Table Storage caps a property at 64 KB and an entity at 1 MB. The analyzers run with returnDetails, enableLayout, and estimateFieldSourceAndConfidence, so multi-page raw responses exceed both limits — writes would fail on exactly the large documents most worth debugging.
Blob sidecar + ledger pointers Chosen No practical size limit, negligible cost, lifecycle-management retention, and stored raw results enable offline replay of the gates (no CU spend, deterministic).
Also store a copy of the original PDF bytes Rejected SharePoint remains the source of the file (SharePointUrl/FileName on the row point back to it); duplicating it would double the PII at rest.
App Insights custom events / dimensions Deferred 32 KB property cap, sampling can drop events, and it would push full invoice PII into telemetry. Invocation-id correlation remains open as hardening item HG-05.

3Design

3.1 Blob layout

functionapp/diagnostics.py writes two blobs per run into the container invoice-diagnostics (override: env DIAGNOSTICS_CONTAINER), under the ledger row's RowKey prefix. The timestamp keeps a run history when the same SharePoint item is re-uploaded and re-processed: 

{rk}/{yyyymmddThhmmssZ}-raw.json       full cu_client analyze result (values, confidences)
{rk}/{yyyymmddThhmmssZ}-decision.json  gates.evaluate result (what the flow received)

Auth mirrors ledger.py: AZURE_TABLES_CONNECTION_STRING if set (a full storage connection string — covers Azurite locally), otherwise AZURE_STORAGE_ACCOUNT + DefaultAzureCredential. No new secrets.

3.2 New ledger columns

ColumnWritten whenMeaning

DecisionBlobExtractedBlob path of the decision JSON ("" if the sidecar write failed).
AnalyzerIdExtractedThe child analyzer that produced the fields (analyzerUsed from the result).
CuDurationMsExtractedWall-clock duration of the CU analyze call; watch for creep toward the 120 s timeout.
FailedStageCU failure"cu_analyze" when the analyze call raised; cleared to "" on the next successful run.
LastErrorCU failurestr(exc) truncated to 1024 chars; cleared to "" on the next successful run.

3.3 Contracts

  • Best-effort sidecar. diagnostics.save_run catches every exception, logs a warning, and returns None. A diagnostics outage can never fail invoice processing; the ledger pointers are simply empty for that run.
  • Failure stamp preserves reclaim semantics. The CU-failure stamp is a merge upsert that does not touch Status, so the row stays at Received and gate A1's staleness lease still governs when a retry may reclaim it. The stamp refreshes LastUpdatedUtc, extending the lease only by the failed CU call's own duration. The stamp itself is wrapped in try/except — the 502 is returned either way.
  • No stamp on ledger-write failure. If the Extracted write fails, the ledger just proved unavailable; the existing ledgerWriteError response field and the exception log line are the record.

4Tooling — scripts/diag.py

Inspect a processed invoice (ledger row + download its diagnostics blobs to out\diag\<rk>\):

.\.venv\Scripts\python.exe scripts\diag.py --source-id <sharepoint-item-guid>

Replay a stored raw result offline — runs gates.evaluate on the stored JSON with no CU call. Use it to reproduce the original decision, or to test a gates.py/field_policy.py change against real historical responses:

.\.venv\Scripts\python.exe scripts\diag.py --replay out\diag\<rk>\<ts>-raw.json
.\.venv\Scripts\python.exe scripts\diag.py --replay ...-raw.json --field-threshold 0.8 --file-name invoice1.pdf
Fault-domain split. If the replayed decision differs from the stored -decision.json, the gates/policy code changed since the run. If the stored raw values themselves are wrong, the problem is on the CU/analyzer side — iterate the prompt on a scratch analyzer with replicates (see docs/ai/troubleshooting.md).

5Operations

  • RBAC: the Function's managed identity needs Storage Blob Data Contributor on the storage account (it previously had only a table role). Dev: stinvoicedevwestus.
  • Retention: add a blob lifecycle-management rule deleting blobs in invoice-diagnostics older than 90 days, matching ledger.DEFAULT_RETENTION_DAYS. Azurite ignores lifecycle rules (local dev unaffected). 
    az storage account management-policy create --account-name <account> -g <rg> --policy '{
  "rules": [{ "enabled": true, "name": "purge-invoice-diagnostics", "type": "Lifecycle",
    "definition": {
      "filters": { "blobTypes": ["blockBlob"], "prefixMatch": ["invoice-diagnostics/"] },
      "actions": { "baseBlob": { "delete": { "daysAfterModificationGreaterThan": 90 } } } } }]
}'
  • PII: the raw CU JSON contains the full invoice text. The container is private, in the same storage account and under the same access controls as the ledger, auto-deleted at 90 days; field values are never written to logs.
